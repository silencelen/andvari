Honeypot traps beside a real login

The filltest site's honeypot page (login/honeypot.html), its form as the site serves it: seven username and password traps around the real fields, each hidden a different way. capture.honeypot.test.ts reads this markup.

  • Only the two real fields fill: the seven traps stay empty.
  • Type a username and a password into the real fields, then Sign in: the save offer holds the password you typed. Until the 0.30.0 release check the capture read the "1 by 1 px" trap instead (empty, so nothing was offered): the page's own input rule draws that trap and the clipped one full width under the next trap, where the detection rules count them as password fields, and three password fields read as a change of password, whose capture is the second.
